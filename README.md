# 📚 RAG Assistant for Research Papers on RAG & LLM Evaluation

An AI assistant that answers questions about 50 recent (2025+) arXiv papers on retrieval-augmented
generation and LLM evaluation. Every answer cites its sources (paper, page), and when the papers
do not contain the answer, the assistant says so instead of guessing. Retrieval and generation are
evaluated separately on a hand-written question set.

---

## 🚀 Features

- 💬 Ask questions in plain English (e.g. *"How does RINSE decide whether retrieved evidence is sufficient?"*)
- 🔎 Retrieval modes: dense vectors (FAISS), **hybrid** dense + BM25 fused with Reciprocal
  Rank Fusion, and **cross-encoder reranking** (default: hybrid + rerank)
- 📌 Citations mapped back to the real paper and page, so the model cannot invent a source
- 🙅 Explicit "I don't know" when the retrieved passages do not contain the answer
- 📊 Evaluation suite: Hit@k, Recall@k, MRR for retrieval; LLM-as-a-judge correctness,
  faithfulness and abstention for generation
- 🖥️ **Streamlit** web demo and a command-line interface

## ⚙️ How it works

```
PDFs ──► parse & clean ──► chunk (1000 chars, 100 overlap) ──► embed (bge-small) ──► FAISS index

question ──► retrieve top-k passages ──► prompt with numbered passages [1]..[k]
         ──► LLM (temperature 0) ──► answer with [n] citations ──► (paper, page)
```

| Component | Choice |
|---|---|
| PDF parsing | PyMuPDF, with header/footer, hyphenation and reference-section cleaning |
| Embeddings | `BAAI/bge-small-en-v1.5` (384-d, CPU) |
| Vector index | FAISS `IndexFlatIP` (exact search) |
| Keyword search | BM25 (`rank-bm25`), fused with dense results by Reciprocal Rank Fusion |
| Reranker | `cross-encoder/ms-marco-MiniLM-L-6-v2` |
| LLM | `qwen/qwen3.8-27b` for answers, `openai/gpt-oss-120b` as judge (Groq API) |

43 hand-written questions: 25 factual, 10 needing several passages, and 8 that the papers cannot
answer (the assistant should refuse). One setting is changed at a time.

**Metrics.** Hit@k: a retrieved passage is on a gold page. Recall@k: share of gold passages found.
MRR: 1 / rank of the first correct passage. Correctness and faithfulness: LLM-judge scores from 0 to
2 with a fixed rubric. Over-refusal: answerable questions the assistant refused. Correct abstention:
unanswerable questions it refused.

### What the results show

- **Retrieval is necessary:** without it the LLM answers 0% of the questions fully correctly; these
  2025+ papers are not in its memory.
- **Chunk size has an optimum:** 1000 characters beats 500 (less context per passage) and 1500
  (blurred embeddings, and 3.8% of chunks exceed the embedder's 512-token limit).
- **More passages is a trade-off:** k=8 finds more evidence but lowers faithfulness (1.93 to 1.75).
- **Hybrid search + reranking is the best retriever:** compared with the dense baseline at k=4, Hit@4
  rises from 74% to 86%, MRR from 0.54 to 0.68, and wrong refusals fall from 20% to 6%, while every
  unanswerable question is still refused. It is the default mode.

### Error analysis

Every failure of the hybrid configuration was labelled with one cause
(`scripts/failure_analysis.py`, `results/failures_hybrid_k4.csv`): 7 of 15 were **ranking**
problems (the right passage was in the top 20 but not the top 4), 3 were retrieval misses, 2 were the
LLM overlooking a fact it was given, 2 were judge issues and 1 was a bug in the evaluator itself,
fixed before comparing configurations. Reranking the hybrid candidates targeted the dominant cause:
retrieval improved clearly, answer correctness stayed level with plain hybrid. The remaining
bottleneck is generation on two-part questions, where the model often answers only one part.

## 🗂️ Project Structure

```
├── app.py                  # Streamlit demo
├── src/rag/
│   ├── download.py         # fetch the arXiv PDFs and their metadata
│   ├── parse.py, clean.py  # PDF text extraction and cleaning
│   ├── chunk.py            # split pages into overlapping chunks
│   ├── embed.py, index.py  # embeddings and the FAISS index
│   ├── retrieve.py         # dense / hybrid / rerank retrieval
│   ├── hybrid.py           # BM25 + Reciprocal Rank Fusion
│   ├── rerank.py           # cross-encoder reranker
│   ├── generate.py         # prompt, LLM call, citation mapping, refusal
│   ├── evaluate.py         # retrieval metrics, LLM judges, results table
│   ├── tools.py            # search_papers(): retrieval as a plain function
│   └── cli.py              # python -m rag.cli ask "..."
├── eval/qa.jsonl           # the 43 evaluation questions with gold passages
├── results/                # per-experiment results and summary.csv
├── scripts/                # experiment, checking and table-generation scripts
├── tests/                  # pytest unit tests
└── corpus/                 # arXiv ids and paper metadata
```

## 🛠️ Setup

Requires Python 3.12 and a free [Groq](https://console.groq.com) API key. CPU only.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
copy .env.example .env              # then put your GROQ_API_KEY in .env

# build the data once (about 15 minutes on CPU); corpus/corpus_ids.txt pins exact
# arXiv versions, so the rebuilt corpus is byte-identical to the evaluated one
$env:PYTHONPATH="src"
.\.venv\Scripts\python.exe -m rag.download
.\.venv\Scripts\python.exe -m rag.parse
.\.venv\Scripts\python.exe -m rag.chunk
.\.venv\Scripts\python.exe -m rag.embed
.\.venv\Scripts\python.exe -m rag.index
```

**Run the demo**

```powershell
.\.venv\Scripts\streamlit.exe run app.py
```

**Or ask from the terminal**

```powershell
.\.venv\Scripts\python.exe -m rag.cli ask "What is faithfulness in RAG evaluation?" --show-chunks
```

**Reproduce the evaluation and run the tests**

```powershell
.\.venv\Scripts\python.exe -m rag.evaluate --mode hybrid --k 4
.\.venv\Scripts\python.exe scripts/make_results_table.py
.\.venv\Scripts\python.exe -m pytest -q
```

## ⚠️ Limitations

- **Small evaluation set:** 43 questions, so differences of one or two questions are not significant.
- **Page-level gold labels:** a hit means the right page, not the exact passage, which makes Hit@k
  somewhat optimistic.
- **LLM judge:** correctness and faithfulness are scored by an LLM, checked on a sample but not by
  independent human annotators. It is least consistent on partially correct answers.
- **Embedding limit:** about 1% of chunks exceed the embedder's 512-token limit and are truncated.
- **Text only:** tables and equations are read as plain text.
